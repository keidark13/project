About

I started writing software the way many engineers in my cohort did — building small things on the side, falling in love with the part where you press save, hit refresh, and something you imagined exists. Twenty years later, the loop is still the most interesting one I know.

My professional career has been mostly in payments and developer platforms. At Stripe I worked on the API client libraries — the things that thousands of integrations call every second. At Vercel I worked on the build and deployment pipeline, the parts you only notice when they break. I am drawn to the layer of software that sits beneath the product, the layer where a single mistake propagates outward into thousands of incident reports.

Outside work I read more than I should, run middle distances badly, and maintain a few open-source TypeScript libraries that have lived longer than several of my employers. I am married, no children, two plants that have somehow survived since 2019.

Selected projects

01

grove

A typed, minimal task runner for TypeScript monorepos. Reads a small config file, builds a dependency graph, runs tasks in parallel with content-hashed caching, and gets out of your way. No plugins, no daemons, no opinions about your bundler.

I built grove because every existing task runner I tried either insisted on running its own dev server, or required a configuration file longer than the code it was orchestrating. It has been used in three production monorepos so far, and is the only tool on this list I would happily depend on tomorrow.

TypeScript Node.js Monorepo CLI
Source Docs
02

lockstep

An opinionated linter for changesets. Reads your repository's changelog files and enforces a small set of rules: every changeset must reference at least one issue, version bumps must match the type of change described, and breaking changes must include a migration note.

The tool came out of a frustration shared with my team at Vercel — the changelog had drifted from being a record of what changed to a place where engineers said vague things to satisfy CI. lockstep does not solve culture, but it makes the cultural decision visible at the point it happens.

TypeScript Changesets CI Linter
Source Docs
03

teal-cache

A small Rust library for content-addressed build caching. Stores artifacts keyed by the hash of their inputs and exposes a tiny stable API to JavaScript via N-API. Used internally at three companies and as the cache layer in grove.

I wrote this because the existing JavaScript-side caches I tried became the bottleneck once a monorepo got beyond a few hundred packages. The Rust core does the hashing and the disk IO; the JavaScript bindings stay deliberately thin. It is the smallest project on this list and probably the one that has earned the most CPU back per line of code.

Rust N-API Caching Performance
Source
04

atlas-types

A TypeScript code generator that reads a Postgres schema and produces a fully typed query layer — including row types, insert types, partial update types, and a small fluent query builder. No runtime dependency on an ORM, no decorators, no magic.

I built atlas-types after spending too many afternoons fighting with Prisma generators and Drizzle's type inference. It is intentionally less powerful than either of those projects. What it does, it does fast and predictably, with type errors that point to the column you misspelled.

TypeScript Postgres Codegen SQL
Source Docs
05

dispatch

A small CLI for sending operational pages from a terminal. Reads a YAML on-call roster, knows about your team's timezones, and writes a paging log that you can later review. Speaks Slack, Pushover, and PagerDuty as backends; speaks plain text to your shell when you are offline.

I built dispatch during a long winter at Heroku, after one too many incidents where the page went to the wrong person because the rotation calendar had not been updated. It is the project I am least proud of architecturally and the one I have re-used in the most places.

Go CLI On-call Ops
Source
06

lockfile-lens

A small static analyser that reads pnpm and npm lockfiles and tells you which transitive dependencies have been added in the last week, which have changed major version, and which now have known CVEs. Designed to run in CI as a five-second pre-merge check.

I wrote lockfile-lens because dependency review on most teams is either nonexistent or theatre. This one runs fast enough that engineers actually read its output, and it is opinionated enough that it occasionally blocks a merge for a reason worth blocking on.

TypeScript Security CI Supply chain
